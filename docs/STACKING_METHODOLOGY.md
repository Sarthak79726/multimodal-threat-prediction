## 1. Theoretical Foundation of Stacking

**Stacked Generalization** (Wolpert, 1992; Breiman, 1996) is an ensemble learning paradigm in which multiple heterogeneous base models (Level 0) generate predictions that serve as input features for a meta-model (Level 1).

In multimodal decision systems, stacking offers distinct advantages over simple linear late fusion:
1. **Heterogeneous Input Integration:** Combines models trained on fundamentally different modalities (wearable physiological time-series, spatial coordinates, environmental factors).
2. **Non-Linear Decision Boundaries:** Enables the meta-model to capture feature interactions (e.g., physiological stress is elevated simultaneously with high location vulnerability).
3. **Calibrated Probabilistic Outputs:** Maps raw scores or base probabilities into a well-calibrated posterior probability distribution, overcoming the poor calibration of raw weighted sums.

## 2. Mathematical Formulation

### Level 0 Input Space
Let $\mathbf{x}_{\text{phys}} \in \mathbb{R}^{76}$ represent extracted physiological features, $\mathbf{x}_{\text{spat}} \in \mathbb{R}^d$ represent spatial coordinates and distance attributes, and $\mathbf{x}_{\text{env}} \in \mathbb{R}^k$ represent environmental situational variables.

The Level 0 base branches map these inputs to continuous scalar scores:
$$P_1 = f_1(\mathbf{x}_{\text{phys}}) = P(\text{Stress} = 1 \mid \mathbf{x}_{\text{phys}}) \in [0.0, 1.0]$$
$$P_2 = f_2(\mathbf{x}_{\text{spat}}) \in [0.0, 1.0]$$
$$P_3 = f_3(\mathbf{x}_{\text{env}}) \in [0.0, 1.0]$$

These scalar outputs constitute the **Meta-Feature Vector**:
$$\mathbf{X}_{\text{meta}} = \begin{bmatrix} P_1 & P_2 & P_3 \end{bmatrix} \in [0.0, 1.0]^3$$

### Level 1 Meta-Learner: Logistic Regression
The primary Level 1 meta-learner implemented in `src/fusion/meta_learner.py` is an L2-regularized Logistic Regression classifier:

$$\text{logit}(P_{\text{threat}}) = z = \beta_0 + \beta_1 P_1 + \beta_2 P_2 + \beta_3 P_3$$
$$P_{\text{threat}} = \sigma(z) = \frac{1}{1 + \exp\left(-\left(\beta_0 + \sum_{i=1}^3 \beta_i P_i\right)\right)}$$

Where:
- $\beta_0$: Intercept term, reflecting base log-odds (prior probability of a threat event occurring when all input scores are 0).
- $\beta_1$: Weight assigned to physiological stress.
- $\beta_2$: Weight assigned to geospatial campus vulnerability.
- $\beta_3$: Weight assigned to environmental risk.
- $\text{Odds Ratio} = \exp(\beta_i)$: Multiplicative factor by which the odds of a threat event increase per unit change in input probability $P_i$.

### Meta-Loss Optimization
The parameters $(\beta_0, \boldsymbol{\beta})$ are fitted by minimizing the penalized binary cross-entropy loss over $N$ training samples:

$$\mathcal{L}(\beta_0, \boldsymbol{\beta}) = -\frac{1}{N} \sum_{k=1}^N \left[ y_k \ln \hat{y}_k + (1 - y_k) \ln(1 - \hat{y}_k) \right] + \frac{\lambda}{2} \|\boldsymbol{\beta}\|_2^2$$

where $\hat{y}_k = \sigma(\beta_0 + \boldsymbol{\beta}^T \mathbf{x}_{\text{meta}, k})$, and $\lambda > 0$ controls L2 weight decay.

## 3. Out-of-Fold (OOF) Training Protocol

A critical failure mode in stacking ensembles is **meta-level data leakage**: if Level 0 predictions used to train the Level 1 meta-model are generated by base models on their own training data, the predictions will be overly optimistic, causing the meta-learner to assign disproportionate weight to overfitted base models.

To eliminate this leakage, our architecture incorporates strict **Out-of-Fold (OOF)** cross-validation in `src/fusion/oof_generator.py` and `src/fusion/stacking_pipeline.py`.

```
Full Training Set (N_train samples across M subject clusters)
┌────────────────────────────────────────────────────────────────────────┐
│ Fold 1 Train: Subj A, B, C... │ Fold 1 Val: Subj D ──► OOF Probs [Fold 1] │
├────────────────────────────────────────────────────────────────────────┤
│ Fold 2 Train: Subj B, C, D... │ Fold 2 Val: Subj A ──► OOF Probs [Fold 2] │
├────────────────────────────────────────────────────────────────────────┤
│ Fold 3 Train: Subj A, C, D... │ Fold 3 Val: Subj B ──► OOF Probs [Fold 3] │
├────────────────────────────────────────────────────────────────────────┤
│ Fold 4 Train: Subj A, B, D... │ Fold 4 Val: Subj C ──► OOF Probs [Fold 4] │
└────────────────────────────────────────────────────────────────────────┘
                                                         │
                                                         ▼
                                          Combined OOF Matrix X_meta^OOF
                                          (Every row predicted out-of-fold)
                                                         │
                                                         ▼
                                          Fit Meta-Learner on X_meta^OOF, y
```

### Steps in the OOF Protocol:
1. **Subject-Grouped Splitting:** Grouped cross-validation (`StratifiedGroupKFold` or `GroupKFold`) ensures no subject or session appears in both the training split and validation split of any fold.
2. **Independent Fold Fitting:** In fold $k$, base models and scalers are fitted exclusively on training indices $\mathcal{I}_{\text{train}, k}$.
3. **Held-Out Inference:** Fitted fold models predict probabilities only for validation indices $\mathcal{I}_{\text{val}, k}$.
4. **Assembly of $\mathbf{X}_{\text{meta}}^{\text{OOF}}$:** Assembling all validation slices yields a full matrix $\mathbf{X}_{\text{meta}}^{\text{OOF}} \in \mathbb{R}^{N_{\text{train}} \times 3}$ where every row was evaluated by a model that never observed that sample or subject during training.
5. **Meta-Learner Training:** The Level 1 meta-learner is fitted exclusively on $(\mathbf{X}_{\text{meta}}^{\text{OOF}}, \mathbf{y}_{\text{train}})$.
6. **Untouched Test Evaluation:** Final evaluation is conducted on an entirely independent, untouched test set ($\mathbf{X}_{\text{test}}, \mathbf{y}_{\text{test}}$) that was partitioned before CV and never touched during hyperparameter tuning.

## 4. Separation of Real Model Training from Simulation

To maintain strict academic integrity, the training codebase in `src/fusion/train.py` is partitioned into two mutually exclusive workflows:

### Workflow A: Synthetic Simulation Demonstration (`run_synthetic_simulation_demo`)
- **Purpose:** Demonstrates pipeline mechanics, OOF cross-validation, mathematical coefficient learning, and calibration metric tracking in a controlled test environment.
- **Data Source:** Synthetic observations drawn from Beta distributions with a mathematical non-linear hazard function.
- **Output Destination:**
  - Artifact: `models/fusion/synthetic_demo/stacking_ensemble_demo.pkl`
  - Reports: `reports/synthetic_simulation/stacking_benchmark_results_synthetic_demo.json`
- **Metadata Tagging:**
  - `dataset_type = "synthetic_simulation"`
  - `production_eligible = False`
- **Production Isolation:** This demo artifact is strictly barred from the production application.

### Workflow B: Production Meta-Model Training (`train_production_stacking_model`)
- **Purpose:** Trains a genuine, production-eligible Level 1 Meta-Learner when a validated empirical dataset is provided.
- **Requirements for Execution:**
  - Must supply a verified CSV/Parquet dataset with real multimodal samples.
  - Requires independent ground-truth physical threat outcome labels.
  - Requires non-overlapping subject/session identifiers.
  - Enforces `validate_multimodal_dataset(..., enforce_production_empirical=True)`.
  - Rejects circular formula labels (`DataCircularityError`).
  - Rejects synthetic datasets (`SyntheticDatasetRejectedError`).
- **Failure Behavior:** If no valid empirical dataset is supplied, the script terminates with a descriptive error message and leaves the production meta-model status as `UNTRAINED — VALID MULTIMODAL THREAT DATASET REQUIRED`.
