# 📋 Dataset and Label Requirements for Production Stacking Model

**Project:** Multimodal Threat Prediction Engine  
**Topic:** Rigorous Specifications for Collecting Empirical Multimodal Threat Data  
**Current Status:** No synchronized multimodal empirical dataset with verified physical threat outcome labels currently exists in this project.

---

## 1. The Core Scientific Requirement

A Machine Learning Stacking Meta-Learner cannot learn genuine real-world threat decision boundaries without:
1. **Synchronized Multimodal Observations:** Simultaneous empirical recordings of human physiology, client geospatial coordinates, and local environmental context.
2. **Independently Verified Outcome Labels:** Ground-truth labels representing actual physical threat or personal safety events, verified independently of the sensor inputs.

Training a stacking classifier on synthetic distributions, formula-derived labels, or isolated laboratory stress labels does not produce an authentic physical-threat prediction engine. This document establishes the exact protocol required before a production stacking model can be legitimately trained.

---

## 2. Temporal Synchronization Requirements

To avoid temporal misalignment artifacts, all three modalities must be synchronized to a unified UTC / IST timestamp standard.

| Modality | Native Sampling Rate | Aggregation Window | Feature Alignment |
|---|---|---|---|
| **ECG (Chest)** | 700 Hz | 60 seconds (sliding, 30s step) | HRV, RMSSD, Mean HR, LF/HF |
| **EDA (Chest/Wrist)** | 700 Hz / 4 Hz | 60 seconds (sliding, 30s step) | Mean tonic, Phasic peak count, SCL |
| **BVP (Wrist)** | 64 Hz | 60 seconds (sliding, 30s step) | Pulse rate variability, Blood volume amplitude |
| **Accelerometer** | 32 Hz / 700 Hz | 60 seconds (sliding, 30s step) | Movement intensity, Jerk, Stillness ratio |
| **GPS Fixes** | 0.2 Hz – 1.0 Hz | Nearest fix within window ($\le 15$s) | Lat, Lon, Accuracy, Haversine to landmarks |
| **Environmental** | Periodic / Sensor log | Window timestamp | Diurnal hour (IST), Lux / Ambient lighting, Crowd estimate |

### Synchronization Verification Protocol:
- **Unified Epoch Timestamps:** Every record must contain an ISO-8601 UTC timestamp and an integer epoch millisecond timestamp (`timestamp_ms`).
- **Maximum Tolerable Drift:** Clock drift between mobile telemetry and physiological sensor recording hardware must not exceed **250 milliseconds**.
- **Windowed Feature Vector:** Each observation row in the multimodal dataset corresponds to an identical time window $[t - 60\text{s}, t]$.

## 3. Target Label Provenance and Ground Truth Integrity

### Permissible Ground-Truth Sources
A legitimate production meta-model requires target labels $y \in \{0, 1\}$ originating from verified physical security records:
1. **Verified Security Incident Reports:** Timestamped and geo-located reports filed with campus security or local law enforcement.
2. **Duress / Panic Alarm Activations:** Confirmed emergency button presses or SOS activations triggered by users experiencing genuine threats.
3. **Controlled Campus Safety Drill Trials:** Approved, IRB-reviewed personal safety drill simulations conducted on campus with human participants where simulated threat actors approach subjects under controlled experimental protocols.

### Strictly Prohibited Label Sources
1. **Circular Mathematical Formulas:** Targets generated by thresholding a weighted combination of input scores (e.g., $y = \mathbb{I}[0.40 \cdot P_1 + 0.25 \cdot P_2 + 0.35 \cdot P_3 \ge 0.50]$) are strictly prohibited. These create circular data leakage where the model merely learns to reverse-engineer its own inputs.
2. **Renamed Physiological Stress Labels:** Re-labelling WESAD Trier Social Stress Test labels as "threat events" is scientifically invalid. Cognitive or affective stress induced by public speaking or mental arithmetic is not equivalent to physical personal danger.
3. **Synthetic Probability Generators:** Fabricating labels via NumPy/SciPy distributions (e.g., non-linear hazard formulas) is permitted only in isolated synthetic simulation tests and must never enter production.

---

## 4. Subject Cohort and Diversity Requirements

To avoid overfitting to individual physiological baselines and specific campus walking routes:

- **Minimum Subject Count:** A minimum of **30 independent human subjects** must participate in data collection.
- **Demographic Diversity:** Participants should represent diverse physiological baselines, resting heart rates, physical fitness levels, and genders to prevent demographic biometric bias.
- **Route Diversity:** Geographic observations must cover diverse campus zones (densely populated academic hubs, residential hostel paths, isolated peripheral boundaries, well-lit vs. unlit paths).
- **Diurnal Coverage:** Data collection must span multiple time periods (morning, afternoon, dusk, late night) to expose the model to genuine environmental variation.

---

## 5. Train / Validation / Test Splitting Protocol

1. **Strict Subject-Level Holdout:** At least **20% of independent subjects** must be placed into a dedicated, untouched test partition before model exploration begins.
2. **Zero Subject Overlap:** No subject identifier present in the test partition may appear in training or validation splits.
3. **Session-Level Grouping:** Multiple recordings from the same subject must be grouped together to prevent intra-subject temporal leakage.
4. **Leakage-Free Cross-Validation:** Out-of-Fold training must utilize `StratifiedGroupKFold` grouped by `subject_id`.

## 6. Dataset Ingestion Validation Schema

Prior to executing `train_production_stacking_model()`, the dataset must pass the programmatic schema validator:

```python
REQUIRED_COLUMNS = [
    "timestamp_iso",
    "subject_id",
    "session_id",
    "p_physiological",     # Derived from real synchronized biosignals
    "p_spatial",           # Derived from real verified GPS
    "p_environmental",     # Derived from real verified context
    "threat_label",        # Verified empirical physical safety outcome
    "incident_id"          # Reference to verified security report or trial log
]
```

Any dataset failing this schema, showing synthetic subject naming, or exhibiting circularity with the baseline formula will be rejected by `validate_multimodal_dataset(..., enforce_production_empirical=True)`.
